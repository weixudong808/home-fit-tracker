# 饮食搭配卡片图规格（3:4）

> 2026-09-09 定稿。起因：手机聊天气泡里连试三种文字呈现都翻车（加粗长列表像说明书 → Markdown 宽表列被挤碎露出 `|---` → 竖排短块多方案仍密），改为卡片图后用户拍板「按着这个大小来」。本文件是 `scripts/diet_card.py` 的渲染规格 + Agent 出图验收清单。

## 1. 尺寸与比例

- 画布 **1080 × 1440**（**3:4**，与首张获用户认可的单方案卡一致）
- **禁止 9:16 海报风**：多方案对比也必须塞进同一 3:4 画布，靠压缩行距/字号，不许拉长
- 安全区：四周留白 ≥ 64px；卡片圆角半径 36px

## 2. 色板（浅薄荷 / 灰绿系）

| 用途 | 色值 |
|---|---|
| 画布底色 | `#E8F0EB`（浅薄荷灰绿） |
| 方案卡底 | `#FFFFFF`（白，圆角） |
| 主文字（深绿） | `#1F3D2B` |
| 次级文字 | `#5A7263` |
| 强调/方案标签 | `#2E7D4F` |
| 分割线 | `#D5E0D8`（1–2px 细线） |

字体：优先 Noto Sans CJK（Linux）/ PingFang（macOS）/ 微软雅黑（Windows），脚本内置查找链，可用 `--font` 强制指定。标题加粗（Medium/Bold 权重）。

## 3. 输入 JSON（结构化，数字的唯一来源）

脚本只负责渲染，**不做任何营养计算**。克数由 Agent 按目标宏量算准（±10g 达标）后写入 JSON。

```json
{
  "title": "今日饮食",
  "subtitle": "目标 碳水165g · 蛋白66g · 脂肪55g",
  "mode": "single",
  "items": [
    {"name": "米饭（熟）", "grams": "600g"},
    {"name": "牛里脊（生）", "grams": "230g"},
    {"name": "青笋", "grams": "350g"},
    {"name": "烹饪油", "grams": "32g"}
  ],
  "footer": "估算值 · 选这套即可"
}
```

多方案（`mode: "multi"`），同一画布内 A/B/C：

```json
{
  "title": "今日饮食 · 三选一",
  "subtitle": "目标 碳水165g · 蛋白66g · 脂肪55g",
  "mode": "multi",
  "plans": [
    {"label": "A", "name": "瘦牛（推荐）",
     "line": "米饭600g · 牛里脊230g · 青笋350g · 油32g",
     "macros": "165 / 66 / 55"},
    {"label": "B", "name": "稍肥牛",
     "line": "米饭560g · 牛肥瘦230g · 青笋350g · 油30g",
     "macros": "160 / 72 / 54"},
    {"label": "C", "name": "分三餐（同A）",
     "meals": [
       {"meal": "早", "grams": "100 / 35 / 50 / 5"},
       {"meal": "午", "grams": "300 / 125 / 200 / 17"},
       {"meal": "晚", "grams": "200 / 70 / 100 / 10"}
     ],
     "macros": "165 / 66 / 55"}
  ],
  "footer": "估算 · 回 A/B/C 即可"
}
```

- `macros` 顺序固定为 碳水 / 蛋白 / 脂肪（g）
- C 类分三餐方案的 `grams` 四元组顺序固定为 米 / 肉 / 笋 / 油，**三餐都必须四个数齐全**

## 4. 布局

### 单方案卡（默认）

```
┌──────────────────────────┐
│  今日饮食                  │  ← 大标题（深绿，粗体）
│  目标 碳水165g · 蛋白66g…  │  ← 副标题（次级色）
│  ────────────────────    │  ← 细分割线
│  米饭（熟）        600g    │  ← 名称左对齐，克数右对齐
│  牛里脊（生）      230g    │     行间距充足，易扫读
│  青笋             350g    │
│  烹饪油            32g    │
│                          │
│  估算值 · 选这套即可        │  ← 页脚（次级色，小字）
└──────────────────────────┘
```

### 多方案卡

同画布纵向排 3 个白圆角子卡：每卡首行「A · 瘦牛（推荐）」（标签强调色），次行食材一行，末行宏量三元组；C 卡三餐各占一行（餐次标签 + 四元组）。页脚同尺寸居底。

## 5. 确定性保证

- 纯 Pillow 绘制，**不用文生图**：同输入两次运行输出文件逐字节一致（md5 相同），数字绝不会被模型改写
- 不嵌入时间戳/随机数；`--out` 不传时默认写 `减脂数据/diet-card.png`（多方案 `diet-card-multi.png`）

## 6. 验收清单（出图后逐项过）

- [ ] 比例 3:4（1080×1440），不是 9:16
- [ ] 手机聊天气泡缩略图下：标题、每行食材、克数、页脚均可读
- [ ] **数字逐个与 JSON 输入核对一致**（重点：分三餐方案的每餐都是四个数，不许"晚餐只剩两个数"）
- [ ] 宏量三元组顺序 = 碳水/蛋白/脂肪
- [ ] 多方案与单方案**同尺寸**；推荐方案有明确标记
- [ ] 回复正文 = 一句短文案 + 附图，无宽 Markdown 表、无说明书式长列表
- [ ] 用户选定后才 `record.py diet` 记表
